# TASKClipboart — исправление буфера обмена и предпросмотра в ArchAuto

Дата анализа: 22.10.2026  
Репозиторий: https://github.com/DeryKams/archauto  
Ветка, по которой прочитаны исходники: `main` (без фиксации commit SHA)  
Статус: **техническое задание, исходники не изменены**.

## 0. Решения и ограничения задачи

1. **N1. Конфиденциальное содержимое:** отдельную обработку, скрытие и фильтрацию `CLIPBOARD_STATE=sensitive` **не внедрять в рамках этого задания**. Не добавлять связанные с этим задачи и не менять поведение менеджера паролей. Это осознанное исключение из объёма работы, а не утверждение о безопасности отображения.
2. **N2. Как можно больше типов:** показывать полезный предпросмотр или осмысленную подпись **для максимально широкого набора MIME-типов**. Не пытаться выдавать бинарные данные за текст: для изображения, файла, PDF и прочих типов допустим значок + тип/имя/размер/разрешение, когда их можно достоверно определить. Нативная миниатюра изображения в стандартном текстовом модуле Waybar не гарантирована и не обязательна.
3. **Ширина виджета Waybar:** **не более 128 CSS-пикселей по горизонтали, включая значок, текст, рамку и внутренние отступы**. Длинный текст — многоточием, панель не должна расширяться. Это **пиксели, не 128 символов**.
4. **Предпросмотр в меню истории (Walker):** ограничить высоту/ширину строк и объём визуального предпросмотра, чтобы длинные записи не раздували окно. **Не обрезать содержимое самой записи в хранилище** и не портить вставку полного исходного значения.
5. **Tooltip Waybar:** ограничить отдельно, чтобы большое содержимое не создавало огромную всплывающую подсказку. Предлагаемый стартовый ориентир: 200–300 символов и 4–6 строк, окончательно выбрать по тестам.
6. **Не менять** действующие хоткеи `Super+V`, остальные бинды Niri, панель батареи, стиль соседних модулей, Zsh, схемы Stow и возможности `--skip-aur`.
7. Разделять: **«подтверждено исходником/официальной документацией»**, **«предлагаемый способ»**, **«не подтверждено на живом Arch/Niri»**. Успешная статическая проверка не является гарантией работы интерфейса.

## 2. Подтверждённые дефекты и точные требования

### C-01. Ширина Waybar задана в обратную сторону — P0

**Доказательство:** в `style.css`, блок `#custom-clipboard`, указано `min-width: 128px`; это **минимальная ширина**, не максимум. В `config.jsonc` указано `max-length: 16`, ограничивающее **число символов**, а не пиксели.

**Симптом:** виджет может занимать больше 128 px, особенно при широких Unicode-символах/другом шрифте.

**Исправление:** убрать принудительное `min-width: 128px` как способ ограничения; предусмотреть внутренние отступы, многоточие и реальную верхнюю границу ширины. `max-length` оставить только как дополнительный защитный лимит символов. Измерять **внешнюю** ширину виджета в GTK Inspector.

**Статус способа:** `[ПОДТВЕРЖДЕНО]` смысл `min-width` и `max-length`. `[НЕ ПРОВЕРЕНО]` что простое добавление `max-width: 128px` заработает в GTK CSS Waybar: GTK поддерживает не весь браузерный CSS. **Не объявлять это готовым исправлением без измерения.** Если модуль не способен зафиксировать ширину штатными средствами, потребуется другой механизм разметки/отрисовки, который надо сначала испытать.

**Приёмка:** при копировании одной буквы, 10 строк, 10 000 символов, CJK/эмодзи ширина внешнего прямоугольника виджета не превышает 128 CSS px; текст не заходит на соседние модули.

### C-02. Нетекстовое содержимое ошибочно называется пустым — P0

**Доказательство:** `clipboard-preview.sh`, строки 14–20 и 31–34. MIME без `text/`, `UTF8_STRING`, `STRING`, `TEXT` приводит к `clipboard=""` и затем к `«Буфер пуст»`.

**Исправление:** разделить состояния `empty`, `text`, `image`, `files`, `html`, `pdf`, `audio`, `video`, `other`, `error` (необязательно все в первой версии). Выводить для каждого полезную подпись, например `Изображение`, `Файлы`, `PDF`, `Аудио`, `Данные: MIME`. Состояние `empty` использовать **только при достоверно пустом буфере**. Пустые нулевой длины данные и `CLIPBOARD_STATE=nil` не путать.

**Проверенный механизм:** Waybar custom JSON поддерживает поля `text`, `tooltip`, `class`, в том числе CSS-классы для статусов. `[ПОДТВЕРЖДЕНО ПО ДОКУМЕНТАЦИИ]`.

**Ограничение:** тип **всегда** можно обозначить лишь при доступных MIME-метаданных; человекочитаемое имя файла/изображение/размер зависят от источника. `[НЕ ГАРАНТИРОВАНО]` для произвольных бинарных MIME.

### C-03. Неограниченное чтение содержимого в память — P1

**Доказательство:** `clipboard="$(cat)"` сначала считывает весь поток; `${clipboard:0:500}` обрезает **после** выделения памяти.

**Исправление:** считывать лишь ограниченный объём полезных данных (предлагаемый первоначальный бюджет 32–64 KiB **для декодирования**, а не для показа), остаток входного потока дочитывать в `/dev/null`. Удерживать в памяти только ограниченное количество байтов и отдельно строить короткий текст для панели/tooltip. Для UTF-8 декодировать с корректной обработкой невалидной последовательности. Не загружать бинарный PNG/PDF целиком ради иконки.

**Что подтверждено:** причина избыточного использования памяти и принцип ограниченного чтения. `[НЕ ПРОВЕРЕНО]` конкретное сочетание `head`/`dd`/`cat` на живом watcher: преждевременное закрытие pipe может повлиять на отправителя, а корректное дочитывание требуется проверить на больших файлах. При необходимости написать маленький Python-обработчик с `sys.stdin.buffer`, лимитом и дочитыванием остатка; Python уже указан в установщике.

### C-04. MIME проверяется не по тому же снимку, что получены данные — P1

**Доказательство:** обработчик получает `stdin` из `wl-paste --watch`, но отдельно обращается к **текущему** буферу через `wl-paste --list-types`. При быстром копировании значения могут относиться к разным предложениям данных.

**Исправление:** использовать согласованный с событием тип, если версия `wl-paste` предоставляет его; иначе реализовать явную проверку невозможности надёжной атомарной классификации и безопасный fallback с тестом быстрой смены типов. Стратегия «перевести watcher на `--type text`» **не подходит**: события нетекстового содержимого могут быть пропущены, на панели останется устаревший текст.

**Критическая версия:** в **wl-clipboard v2.3.0** `run_paste_command()` устанавливает `CLIPBOARD_STATE`, но **не `CLIPBOARD_TYPE`**. В более новом коде ветки `master` переменная `CLIPBOARD_TYPE` появилась. Для Arch-пакета `1:2.3.0-1` **нельзя** применять рецепт с `CLIPBOARD_TYPE` как безусловно рабочий. `[ПОДТВЕРЖДЕНО ПО ИСХОДНИКАМ v2.3.0]`.

**Неопределённость:** полностью атомарный способ получить MIME **того же предложения** без новой версии/иного API здесь **не проверен**. Не проектировать на предположении, что `--list-types` относится к предыдущему событию.

### C-05. Ошибка чтения типов маскируется как пустой буфер — P1

**Доказательство:** `types="$(wl-paste --list-types 2>/dev/null)" || types=""` подавляет stderr, а затем пустое значение трактуется как отсутствие текста.

**Исправление:** отдельно проверять код завершения; при сбое формировать JSON `class="error"`, краткий `text="Буфер: ошибка"`, диагностическое сообщение писать только в stderr/журнал (без содержимого скопированного). `[ПОДТВЕРЖДЁННЫЙ СПОСОБ]` разделение статусов и поддержка JSON/CSS-классов Waybar. `[НЕ ПРОВЕРЕНО]` частота этого сбоя в реальной сессии.

### C-06. Поддерживается слишком узкий набор читаемых форматов — P1

**Доказательство:** текущая классификация допускает произвольное `text/*` и старые X11-имена, остальное считает пустотой. `text/html` может оказаться сырым HTML, а `text/uri-list` — строками URI, не именами файлов.

**Требуемая таблица форматов:**

| MIME или группа | Предпочитаемый предпросмотр | Надёжность до теста |
|---|---|---|
| `text/plain`, `text/plain;charset=utf-8`, `UTF8_STRING`, `STRING`, `TEXT` | Короткий нормализованный текст | Основа решения проверяема |
| `text/html` | Сначала предложенный `text/plain`, иначе «HTML» или безопасно извлечённый текст | HTML→текст требует тестов |
| `text/uri-list` | Количество ссылок/файлов и короткое имя первого | Требуется проверка формата URI |
| `x-special/gnome-copied-files`, аналогичные file-list MIME | «Файлы» + имя, если извлекается | Не везде одинаковый формат |
| `image/png`, `image/jpeg`, `image/webp`, `image/bmp`, `image/svg+xml`, `image/gif` | Значок/метка «Изображение», возможно размеры | Размеры/миниатюры **не гарантированы** |
| `application/pdf` | «PDF» | Группа определяется по MIME |
| `audio/*`, `video/*` | «Аудио», «Видео» | Группа определяется по MIME |
| `application/json`, `application/xml` | Сначала короткий безопасный текст, иначе имя формата | Зависит от содержимого |
| Любой иной MIME | «Данные: тип» без чтения бинарного потока в строку | Корректный fallback |

Для объектов с несколькими MIME выбирать **наилучшее представление** (обычно `text/plain` для текста и HTML; для скопированного файла — имя/URI; для изображения — явный тип), а не просто первый элемент списка. Не обещать миниатюры картинки непосредственно в стандартном модуле `custom/clipboard` Waybar: документация этого модуля описывает текст, формат, tooltip, CSS-классы, но не API для передачи бинарной картинки в JSON. `[ТРЕБУЕТ ДРУГОГО ВИДЖЕТА/ПРОВЕРКИ]`.

### C-07. Пробельные строки ошибочно объявляются пустыми — P2

**Доказательство:** `[[ -z "${clipboard//[[:space:]]/}" ]]` истинно для строки из пробелов/табуляций/переносов.

**Исправление:** не смешивать пустой буфер и текст из одних пробелов. Показывать «Пробелы» или «Пустой текст» в зависимости от нулевой длины, но не `«Буфер пуст»`. `[ПОДТВЕРЖДЕНО ПО BASH-КОДУ]`.

### C-08. Стартовое состояние принудительно неверное — P2

**Доказательство:** главный процесс `clipboard-preview.sh` перед запуском watcher немедленно печатает `«Буфер пуст»`, хотя clipboard мог быть заполнен.

**Исправление:** убрать заведомо ложную заглушку; обеспечить начальное получение состояния/первого события. **Не утверждать, что `wl-paste --watch` всегда мгновенно обновит при старте, пока это не проверено на Niri/установленной версии.** `[ПОДТВЕРЖДЁН ДЕФЕКТ ВЫВОДА, СПОСОБ ИНИЦИАЛИЗАЦИИ ПРОВЕРИТЬ]`.

### C-09. Tooltip ограничен 500 символами и может оставаться слишком большим — P2

**Доказательство:** один и тот же `clipboard` длиной до 500 символов выводится как `text` и `tooltip`. Комментарий `«полный текст»` в Waybar неверен: исходный текст уже обрезан.

**Исправление:** формировать **разные** строки: компактную для Waybar, ограниченную по символам/строкам для tooltip, а полные данные оставлять в буфере/истории. Например, начать с 256 символов/5 строк и проверить размеры окна GTK. Tooltip не должен содержать мегабайт текста. `[ПОДТВЕРЖДЕНО]` разные поля `text` и `tooltip`; `[ПРОВЕРИТЬ]` фактический размер при текущих шрифтах/масштабе.

### C-10. Клик и `Super+V` скрывают ошибки — P2

**Доказательство:** и `config.jsonc`, и `config.kdl` используют практически одинаковую команду: если нет `walker`, ничего не происходит. Проверки `elephant.service`/Clipboard Provider нет.

**Исправление:** общий новый `clipboard-history.sh`, который проверяет `command -v walker`, сообщает понятную ошибку при отсутствии программы, затем запускает `walker --provider clipboard` и отдаёт код ошибки. По возможности выдавать графическую нотификацию при наличии SwayNC/`notify-send` и логировать stderr. И Waybar, и Niri вызывают **один** этот скрипт. Никакого запуска `fuzzel` как «истории» — это другое приложение.

`walker --provider clipboard` — правильная форма запуска, менять на устаревшее `--modules clipboard` **не нужно**. `[ПОДТВЕРЖДЕНО]` дублирование и молчаливое отсутствие Walker; `[НЕ ПРОВЕРЕНО]` доставка уведомлений из конкретной графической сессии.

### C-11. Не проверено, что Elephant и Clipboard Provider стартуют — P1

**Доказательство:** `niriV2.sh` устанавливает `walker elephant elephant-clipboard`, создаёт `~/.config/systemd/user/elephant.service` и символическую ссылку в `niri.service.wants/`. Успешная установка пакетов не равна успешному старту сервиса/провайдера.

**Исправление:** документировать/добавить post-login-проверку в пользовательской сессии:

```bash
# Проверяем фонового поставщика истории
systemctl --user status elephant.service --no-pager

# Проверяем загрузку провайдера Clipboard
elephant listproviders

# Если история не работает, читаем ошибки именно пользовательской службы
journalctl --user -u elephant.service -n 80 --no-pager
```

**Важный контекст:** `elephant` должен стартовать с корректным **пользовательским окружением**, а не как системный root-сервис. Проверить сценарий GDM → `niri-session`/`niri.service`; для ручного `niri` схема может отличаться. Не запускать `systemctl --user` в chroot как будто есть полноценная графическая сессия. `[ПОДТВЕРЖДЕНО]` команда `elephant listproviders` и требования к окружению по README Elephant; `[НЕ ПРОВЕРЕНО]` что данный unit корректно стартует у пользователя.

### C-12. `--skip-aur` оставляет кнопку истории без функции — P2

**Доказательство:** Walker/Elephant ставятся в AUR-ветке `niriV2.sh`; Waybar и `Super+V` существуют и без AUR.

**Исправление:** интерфейс должен показывать отсутствие истории или давать понятное сообщение (без ложного обещания Fuzzel-истории). Виджет **текущего буфера** на базе `wl-clipboard` должен продолжать функционировать. `[ПОДТВЕРЖДЕНО ПО УСТАНОВЩИКУ]`.

### C-13. Два пакета, относящихся к истории — P3 / не подтверждённый дефект

**Доказательство:** AUR-список содержит и `elephant-clipboard`, и `wl-clipboard-history-git`. В изученных связях Niri/Waybar/Walker используется первый; явного вызова второго в анализируемых файлах нет.

**Решение:** перед удалением `wl-clipboard-history-git` найти, используется ли он в других скриптах/службах реального компьютера. Если не используется — убрать лишний пакет из **будущей** установки. **Не удалять текущий пакет автоматически**. `[НЕ ПОДТВЕРЖДЕНО КАК КОНФЛИКТ]`.

### C-14. Буфер может исчезать после закрытия источника — гипотеза

**Описание:** в Wayland предоставление содержимого может зависеть от приложения, которое его скопировало. История Elephant и **текущая** selection могут расходиться.

**Действие:** воспроизвести «копировать → закрыть приложение → проверить `wl-paste` и Walker». Не добавлять автоматически `wl-clip-persist` или другой менеджер до подтверждения симптома: это **дополнительный механизм**, не доказанное исправление текущего дефекта. `[ТРЕБУЕТ ВОСПРОИЗВЕДЕНИЯ]`.

## 3. Компактный предпросмотр в окне Walker (N2)

Это **другое место**, не `#custom-clipboard` Waybar и не его `tooltip`.

Существующая тема: `desktop/.config/walker/themes/apple-dark/style.css`. В ней есть стили `.item-box`, `.item-text` (через общую стилизацию), `.item-subtext`, `.preview`, но **нет отдельной настройки длины clipboard-элементов**. Тема Walker наследует отсутствующие шаблоны из `default` (по документации Walker). В текущем репозитории отдельный `item_clipboard.xml` не обнаружен.

**Задачи:**

1. Ограничить максимальную визуальную ширину и высоту текста в строках Clipboard; длинные записи показывать с многоточием/не более 1–2 строк, без изменения данных Elephant.
2. Сохранить кликабельность, горячие клавиши, поиск и вставку **полной** записи.
3. Ограничить отдельно панель `.preview`: заданные габариты + прокрутка/обрезка текста, чтобы окно не росло при больших данных.
4. Не ухудшить картинки в истории Elephant: поддержка текстовой и графической истории подтверждается документацией самого Elephant; форма миниатюры в конкретном Walker требует теста.
5. Сначала попробовать точечные правила темы. Если одна CSS-тема не ограничивает реальную разметку — создать `item_clipboard.xml` с GTK4 Label `ellipsize` и подходящими размерами, **но только после проверки идентификаторов/контрактов штатного XML для установленной версии Walker**.

**Проверено:** Walker поддерживает `item_clipboard.xml`, `preview.xml`, `style.css`, GTK4-шаблоны и наследование от стандартной темы. `GtkLabel` GTK4 поддерживает `ellipsize`, `max-width-chars`, `lines`; это документированные свойства GTK, **но их точная применимость к текущему Walker-шаблону без проверки не гарантирована**.

**Не делать:** не обрезать текст на уровне `elephant-clipboard` или очищать базу истории; не пытаться управлять размером Walker через CSS Waybar.

## 4. Что НЕ требуется «исправлять»

- `wl-paste --watch` + постоянный поток JSON Waybar — поддерживаемая модель; `interval` добавлять **не нужно**.
- `restart-interval: 5` — допустимо для непрерывного скрипта; это не частота опроса содержимого.
- `exec-on-event: false` — соответствует модели работы: клик открывает Walker и не должен перезапускать watcher.
- `escape: true` — оставлять: скопированный текст может содержать символы разметки.
- `walker --provider clipboard` — оставить как рабочую форму вызова.
- `Super+V` — не переименовывать и не создавать второй конфликтующий бинд.
- `sensitive` — согласно N1 специально не обрабатывать в этом задании.

## 5. Порядок реализации

1. **База:** исправить статусы `empty / text / other / error` и раздельные поля `text`/`tooltip`, сохранить потоковый JSON.
2. **MIME:** расширить представления типов и fallback, **не читая бинарные данные как строку**. Отдельно задокументировать проблему атомарности MIME для `wl-clipboard 2.3.0`.
3. **Ресурсы:** ограничить объём обрабатываемого потока, обеспечить дочитывание, проверить UTF-8 и большие файлы.
4. **Геометрия Waybar:** добиться **измеренных <=128 CSS px**, не подменяя это «16 символами».
5. **Меню Walker:** компактные строки Clipboard и отдельный ограниченный preview; убедиться, что копирование/вставка полные.
6. **Запуск:** единый скрипт открытия истории, диагностика Elephant, понятное поведение `--skip-aur`.
7. **Проверки:** добавить самотестирование без запуска полного установщика на рабочей машине.

## 6. Матрица приёмочных тестов

| Сценарий | Waybar (не более 128 px) | Walker/история | Подтверждение |
|---|---|---|---|
| Пустой clipboard | «Буфер пуст» | Не появляется ложная запись | Через `wl-paste` и UI |
| Обычный русский/английский текст | Короткая строка с многоточием | Полное содержимое доступно для вставки | Сравнить с оригиналом |
| 100 KiB–10 MiB текста | Нет зависания/всплеска памяти | История не обрезана задачей Waybar | Замер памяти и вставка |
| Unicode, emoji, CJK, RTL, символы `<>&` | Корректная строка/экранирование | Корректная вставка | Снимок + сравнение |
| Текст только из пробелов/переводов строк | Не «Буфер пуст» | Корректный элемент | Копирование тестовых данных |
| HTML + plain text | Предпочитается читаемый текст | Вставка сохраняет ожидаемые форматы | В браузере/редакторе |
| URI / один или несколько файлов | «Файлы» или имя | Файловые данные не ломаются | Файловый менеджер |
| PNG/JPEG и другие изображения | «Изображение», не «Буфер пуст» | Элемент/картинка доступны, если поддержаны Elephant | Скриншот и вставка |
| PDF/неизвестный binary MIME | «PDF» или «Данные: MIME» | Не возникает мусора/полного дампа | Форматный тест |
| Быстрая смена `текст → изображение → текст` | Нет устаревшего текста | Соответствует последней selection | 20–50 повторов |
| Перезапуск Waybar при заполненном буфере | Нет устойчивого ложного «Буфер пуст» | История остаётся | Наблюдение после рестарта |
| Walker установлен, Elephant не запущен | Виджет текущего буфера работает | Диагностируемое сообщение | Остановка только user-service в тесте |
| `--skip-aur` | Виджет работает | Нет «немой» кнопки | Изолированная тестовая установка |
| Копирование → закрытие источника | Состояние корректное | Сравнение с историей | Отдельный эксперимент |

**Важное ограничение:** тестовые `wl-copy`/`wl-copy --clear` меняют настоящий буфер текущей сессии. Перед такими тестами сохранить важное содержимое и не запускать сценарии в рабочей среде без намерения менять clipboard. Не выполнять `niriV2.sh` ради тестирования данного узла.

Пример ручного теста (в настоящей сессии Niri, команды **изменяют** буфер):

```bash
# Копируем текст и проверяем доступные форматы
printf 'Тест: UTF-8 & < >\n' | wl-copy --type text/plain
wl-paste --list-types

# Имитируем очистку и проверяем состояние индикатора
wl-copy --clear

# Для проверки картинки использовать настоящий корректный PNG-файл:
# wl-copy --type image/png < /path/to/test.png
```

Контроль перед внесением патча:

```bash
# Проверка исходного Bash без исполнения
bash -n desktop/.config/waybar/scripts/clipboard-preview.sh

# После исправлений: проверить JSON-тесты и условия ошибок
# Сценарий тестов должен подменять wl-paste моками и НЕ читать личный буфер.

# Диагностика реального backend в графической сессии:
systemctl --user is-active elephant.service
elephant listproviders
journalctl --user -u elephant.service -n 80 --no-pager
```

## 7. Отмеченные неточности и непроверенные предположения

**Не ориентироваться как на готовое исправление:**

- `max-width: 128px` в CSS Waybar — пока **нет подтверждения**, что эта декларация в GTK CSS ограничивает фактическую ширину нужного Label/внешнего модуля; результат должен быть **измерен**.
- `CLIPBOARD_TYPE` — **не существует** в `wl-clipboard v2.3.0`, хотя присутствует в новой ветке upstream. Нельзя использовать без проверки установленной версии.
- Конкретный способ устранить гонку `wl-paste --watch` stdin / `wl-paste --list-types` **не подтверждён** для v2.3.0; приоритет — не допускать неверного или бинарного текста и измерить частоту гонки.
- Уменьшение/обрезка Clipboard-строк только CSS Walker **не подтверждена** для текущего `apple-dark`: может потребоваться GTK4 XML и другой механизм управления размерами.
- Миниатюра изображения **в самом стандартном custom-модуле Waybar** и универсальный предпросмотр произвольного бинарного MIME **не подтверждены**. Надёжный fallback — осмысленный тип/иконка.
- Конкретная реализация дочитывания большого бинарного pipe после лимита требует тестов; не считать `head -c 512` единственным достаточным патчем.
- Наличие/отсутствие конфликта `wl-clipboard-history-git` и Elephant **не доказано**. Нельзя удалять пакет только по этому предположению.
- Схема автоматического старта `elephant.service` зависит от реальной графической сессии и требует `systemctl --user`/`journalctl` непосредственно в Arch Linux.
- Если после выхода приложения буфер пуст — это **гипотеза**, до воспроизведения дополнительный clipboard daemon не устанавливать.

## 8. Критерии завершения всей задачи

- [ ] Назначение каждого изменённого файла и каждой новой функции описано короткими комментариями в коде.
- [ ] Waybar не шире **128 CSS px** при всех проверенных форматах; ширина измерена в UI, не только оценена по символам.
- [ ] Нетекстовый clipboard не обозначается как пустой; при незнакомом MIME есть корректный fallback.
- [ ] UTF-8, переносы, специальные символы и большие объёмы не ломают JSON, UI и реакцию watcher.
- [ ] Нормально различаются `empty`, `other`, `error`; очистка не показывает устаревший текст.
- [ ] Tooltip ограничен; строки/панель истории Walker компактны, но оригинальные записи не повреждены.
- [ ] Клик Waybar и `Super+V` одинаково открывают историю либо дают полезную ошибку.
- [ ] При `--skip-aur` остаётся работающий индикатор текущего буфера и понятная недоступность истории.
- [ ] Не добавлена специальная фильтрация `sensitive` (решение N1).
- [ ] `bash -n`, валидность JSONC, тесты с моками, `niri validate`, проверка Walker/Elephant и живые тесты завершены; результаты записаны отдельно, а неподтверждённые пункты не объявлены исправленными.
