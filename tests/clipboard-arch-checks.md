# Приёмка буфера в Arch/Niri

Выполнять после входа в пользовательскую графическую сессию. Эти проверки на macOS не выполнялись.

1. Проверить `systemctl --user status elephant.service --no-pager` и `elephant listproviders`. При ошибке посмотреть `journalctl --user -u elephant.service -n 80 --no-pager`. Службу должен запускать пользовательский сеанс, не root.
2. Открыть историю через кнопку Waybar и `Super+V`; проверить отсутствие Walker, неработающий Elephant, текст и изображение. Полная вставка должна совпадать с источником.
3. В GTK Inspector Waybar измерить внешнюю ширину `#custom-clipboard` с иконкой, рамкой и отступами для короткого текста, CJK, emoji и длинного текста. Критерий: не более 128 CSS px. Текущая конфигурация этого строго не гарантирует.
4. Проверить появление первого состояния после запуска Waybar, очистку, смену `текст → изображение → текст` 20–50 раз, HTML с plain text, файлы и ошибку доступа к буферу. Сравнить текущую selection с текстом виджета; MIME в wl-clipboard 2.3.0 не привязан к stdin watcher.
5. В Walker проверить ширину и высоту строк Clipboard и preview на длинном тексте и изображениях. Если шаблон текущей версии не даёт нужных ограничений, потребуется сверить его XML и добавить точечное переопределение.

Тестовые `wl-copy` и `wl-copy --clear` меняют реальный буфер. Запускать их только после согласованной подготовки тестовой сессии.
